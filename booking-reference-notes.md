# Booking-Inspired UX Reference Notes

Reference reviewed: [Booking.com home](https://www.booking.com/).

The core pattern to adapt is a compact global header followed by a bold, high-contrast search band. The search surface uses one continuous row with destination, date range, and occupancy controls, plus a strong search action. The content hierarchy is discovery-first: trust/value propositions, offer or deal modules, trending destinations, and property-type browsing.

For StayNest, the redesign will preserve the official StayNest wordmark, Ghana-focused content, GHS/USD currency support, BillFlow/manual availability source labels, and current booking logic. The interface will use a denser search bar, structured filter chips, an explicit results count, list-first property cards with prominent media, badges, review summary, availability/source cues, and a clear price/CTA column. It will not copy Booking.com branding, text, imagery, or proprietary UI assets.

The public result flow should remain accessible on mobile by stacking search fields, keeping filters reachable as a compact control, and preserving a prominent search action. Partner and account surfaces will reuse the same spacing and hierarchy but retain StayNest-specific operations.

## Adaptation Scope

| Area | StayNest adaptation |
|---|---|
| Header | Wordmark, destination-oriented navigation, compact account action |
| Search | Dense destination/date/guest row, strong primary action, mobile stacking |
| Results | List-first cards, filter rail/chips, review and price hierarchy, availability labels |
| Discovery | Offers, destinations, property types, and trust signals using Ghana-focused copy |
| Brand guardrails | Keep StayNest colors, typography, logos, imagery, and own content |
| Functional guardrails | Preserve live BillFlow data and computed non-BillFlow availability |

Saved for implementation context; no third-party assets were copied.
